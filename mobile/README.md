# 2D Ledger mobile app (Flutter) — v0.3

One app for both roles. The login screen has a **Client / Admin** switch.

- **Admin** (phone + password): client list + search, create client (name + email), generate a one-time login code for a client, edit name/email, sign a client out of all devices, deactivate/reactivate, change own password.
- **Client** (email + 6-digit code from the Admin; no password; one phone per client): own profile. The ledger from `ledger_v30.html` (commission users, vouchers, numbers, cover, history) and offline drafts/sync come in the next stage.
- Tokens are kept in the iOS Keychain / Android Keystore. The app reopens signed in without internet; it refreshes the access token automatically and returns to the login screen if the refresh token is rejected.

## 1. Install Flutter on your Mac (one time)
1. Install **Xcode** from the App Store, open it once, then in Terminal:
   ```bash
   sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
   sudo xcodebuild -runFirstLaunch
   sudo xcodebuild -license          # type: agree
   xcodebuild -downloadPlatform iOS  # iOS Simulator
   ```
2. Install the Flutter SDK by following https://docs.flutter.dev/install/manual (or `brew install --cask flutter` if you use Homebrew).
3. Install CocoaPods: `brew install cocoapods`
4. Run `flutter doctor` and fix what it lists for **Flutter** and **Xcode**. Android/Chrome warnings can be ignored until you test on Android.

## 2. Create the platform folders (one time)
The ZIP has `lib/` and `pubspec.yaml` only. From this `mobile` folder:
```bash
flutter create --project-name ledger_app --org com.yourname --platforms=ios,android .
flutter pub get
flutter test
```
`flutter create` keeps the existing `lib/`, `pubspec.yaml` and `test/` files.

## 3. Run (backend and database must be running)
```bash
open -a Simulator
flutter run
```
- iOS Simulator reaches the backend at `http://localhost:3000` (default).
- Android emulator uses `http://10.0.2.2:3000` (default). It also needs plain-HTTP allowed for development: in `android/app/src/main/AndroidManifest.xml` add `android:usesCleartextTraffic="true"` to the `<application ...>` tag. Remove it once the API is on HTTPS.
- Real phone on the same Wi-Fi: use your Mac's IP, e.g.
  `flutter run --dart-define=API_URL=http://192.168.1.20:3000`

## 4. First test
1. Sign in as **Admin** with the phone and password from `npm run create-admin`.
2. Tap **New client**, enter a name and an email. A 6-digit login code is shown once; write it down or tap Copy.
3. Sign out, switch to **Client**, enter that email and the code. The code works once.
4. Back as Admin, open the client and tap **Generate login code** to issue another.

## Production notes
- Use HTTPS only; remove the cleartext setting.
- Set the real API address with `--dart-define=API_URL=https://...` at build time.

## Ledger (v0.6)

Client home = tabs Users / Bets / Numbers / Cover / History, plus a menu for draw results, blocked numbers, finalize and sign-out. Data lives in `ledger_data.json` in the app's private folder; every change is queued as an operation and synced automatically (every 30 s, on app resume, after each change, or via the cloud icon). Run `flutter pub get`, `flutter test`, then `flutter run`.

## Language (v0.6.2)

Myanmar (default) and English. Switch on the login screen, or from the ⋮ menu (Admin and Client). All texts are in `lib/i18n/strings.dart` — add every new key to both maps (`test/i18n_test.dart` checks this).

## Client app vs Admin app (v0.6.8)

Build the app you hand out to clients WITHOUT the Admin login:

```
flutter build apk --release --dart-define=APP_MODE=client --dart-define=API_URL=https://your-server
```

`APP_MODE=admin` builds an Admin-only app for yourself. Without `APP_MODE` (normal `flutter run`) both logins are shown.
In a client build the Admin login is not on screen and is refused in code; a saved Admin session is ignored.
The server still decides who is Admin (phone + password), so this is an extra layer, not the only protection.

## App icons (v0.7.4)

Source images are in `assets/icon/` (`client.png` / `admin.png` 1024×1024, plus `*_foreground.png` for Android adaptive icons).
After changing them, run `dart run flutter_launcher_icons`. It reads `flutter_launcher_icons-client.yaml` and `-admin.yaml` and writes
`android/app/src/client/res` and `android/app/src/admin/res`, so each Android flavor gets its own icon.
iOS has no flavors yet, so its single `AppIcon` is the client icon (regenerated by hand from `client.png`).
